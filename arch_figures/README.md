# Control-system architecture figures

Editable draw.io figures of the control system implemented under `hardware/`
(`rtl/src/control_system` — a 1:1 port of the SystemC emulator — and
`compiler/control_system`). Everything here is generated by
`gen_arch_figures.py` from one layout model per figure, so the `.drawio` files
and the `.svg` previews always agree.

```
arch_figures/
├── gen_arch_figures.py        # generator (python3, no dependencies)
├── control_system_all.drawio  # ALL figures as pages of one draw.io file
├── drawio/<name>.drawio       # one file per figure (uncompressed XML)
└── svg/<name>.svg             # preview rendered by the generator
```

## Opening / editing in draw.io

* **Desktop app or app.diagrams.net**: `File → Open` (or drag-and-drop) a
  `.drawio` file. `control_system_all.drawio` shows every figure as a page tab.
* **VS Code**: with the *Draw.io Integration* extension, just open the file.
* The files are uncompressed `mxGraphModel` XML: every box, edge, label and
  colour is a normal draw.io object — move, restyle, add or delete freely.
  Edges use draw.io's orthogonal router with fixed exit/entry points and a few
  waypoints, so after moving a block you may want to re-route the attached edges
  (select the edge → `Edit → Clear waypoints`) or drag the waypoints.
* Export for the paper: `File → Export as → PDF / SVG` (tick *Crop*,
  untick *Include a copy of my diagram* for a clean vector).

Regenerate after editing the generator: `python3 arch_figures/gen_arch_figures.py`
(this **overwrites** the files; keep hand-edited copies under another name).

## Conventions

* **Colours** (same in all figures): blue = measurement / detector data
  (+valid, finish, attempt), thick blue = buses; red dashed = control events
  / command words; orange dashed = post-select (reject); gold = regfile
  address / word and compiled `.mem` programs; purple dashed = local reset /
  gating; grey = status / handshake; green = state machines.
* **Shapes**: white rounded = logic block; yellow = memory / regfile (with the
  `.mem` file that initialises it); blue = FIFO; purple = combinational
  function; grey = register; dashed white = glue / external entity; pills =
  module ports (left = inputs, right = outputs).
* Parameter names, port names and signal names are the RTL's, so a figure can
  be cross-checked against the module header it cites.
